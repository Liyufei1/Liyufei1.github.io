Boost Graph Library (BGL) 核心概念与使用指南

2026-07-02
阅读时长: 7 分钟

Graph

Boost Graph Library (BGL) 是 Boost 库中用于图数据结构和算法的泛型库。它的设计思想与 STL 一脉相承：通过概念 (Concepts) 分离接口与实现，使得同一套算法可以作用于不同的图数据结构。

1. 核心概念：graph_traits

BGL 不依赖具体的图类型，而是通过 graph_traits 萃取图的相关类型。这与 STL 中 iterator_traits 的设计完全一致。

#include <boost/graph/adjacency_list.hpp>
#include <boost/graph/graph_traits.hpp>

typedef boost::adjacency_list<boost::vecS, boost::vecS, boost::directedS> Graph;

// 通过 graph_traits 获取图的各个关联类型
typedef boost::graph_traits<Graph>::vertex_descriptor   Vertex;       // 顶点描述符
typedef boost::graph_traits<Graph>::edge_descriptor     Edge;         // 边描述符
typedef boost::graph_traits<Graph>::vertex_iterator     VertexIter;   // 顶点迭代器
typedef boost::graph_traits<Graph>::edge_iterator       EdgeIter;     // 边迭代器
typedef boost::graph_traits<Graph>::out_edge_iterator   OutEdgeIter;  // 出边迭代器
typedef boost::graph_traits<Graph>::in_edge_iterator    InEdgeIter;   // 入边迭代器
typedef boost::graph_traits<Graph>::adjacency_iterator  AdjIter;      // 邻接顶点迭代器

描述符 (descriptor) 是 BGL 中的核心抽象：它类似于 STL 中的迭代器，用于指向图中的某个顶点或某条边。对于 vecS 作为顶点容器的图，vertex_descriptor 本质上就是一个整数索引。

BGL 定义了一套图概念层级，每个概念规定了图必须支持的接口：

概念 提供的操作
Graph 基础的图类型，不含任何遍历能力
IncidenceGraph out_edges(v, g), source(e, g), target(e, g)
BidirectionalGraph in_edges(v, g), degree(v, g)
AdjacencyGraph adjacent_vertices(v, g)
VertexListGraph vertices(g) — 遍历所有顶点
EdgeListGraph edges(g) — 遍历所有边
MutableGraph add_vertex(), remove_vertex(), add_edge(), remove_edge()

算法通过概念约束图类型：例如 Dijkstra 最短路径需要 VertexListGraph + IncidenceGraph，而拓扑排序还需要 BidirectionalGraph（或等效的出/入度信息）。

2.1 容器选择器

选择器 底层容器 特点
vecS std::vector 随机访问快，删除会导致迭代器失效；顶点自动获得 [0, n) 的索引
listS std::list 删除不失效迭代器，但没有自动顶点索引
setS std::set 自动去重，适合需要检查平行边的场景

vecS 是最常用的选择——速度快，且自动提供 vertex_index 属性，这是大多数算法正常运行的前提。

2.2 方向选择器

选择器 含义 内存开销
directedS 有向图，只存储出边 低
undirectedS 无向图，每条边双向可达 低
bidirectionalS 有向图，同时存储出边和入边 高（约为 directedS 的两倍）

选择 bidirectionalS 的唯一理由是需要 in_edges(v, g) 操作。如果算法不需要访问入边，直接用 directedS 即可。

5. Property Map —— 属性映射

Property Map 是 BGL 中最关键的设计之一。它提供了一种统一接口来访问图的内外部属性，使得算法无需关心数据实际存储在哪里。

当图通过模板参数绑定了内部属性时，通过 get() 获取 property map：

// 用 property 嵌套来组合多个顶点属性
typedef boost::adjacency_list<
    boost::vecS, boost::vecS, boost::directedS,
    boost::property<boost::vertex_distance_t, int,
        boost::property<boost::vertex_name_t, std::string>
    >
> MyGraph;

MyGraph g;
// 获取内建的顶点索引（vecS 自动提供）
auto index_map = get(boost::vertex_index, g);

// 获取自定义的顶点距离属性
auto dist_map = get(boost::vertex_distance, g);

// 写入属性
put(dist_map, 0, 100);    // 顶点 0 的距离设为 100
int d = dist_map[0];      // 读取顶点 0 的距离
// 或使用 free function 写法：
int d2 = get(dist_map, 0);

5.2 外部属性

更常见的做法是将属性存储在外部容器中（如 std::vector），然后包装为 property map 传递给算法：

1
2
3
4
5
6
7
8

int num_v = num_vertices(g);
std::vector<int>    distances(num_v);       // 外部存储距离
std::vector<Vertex> predecessors(num_v);    // 外部存储前驱

// 直接传递 vector 的首地址——BGL 会将其视为 property map
dijkstra_shortest_paths(g, start_vertex,
    boost::distance_map(&distances[0])
        .predecessor_map(&predecessors[0]));

这种外部属性的方式不需要修改图类型定义，更加灵活。&vec[0] 之所以可以直接作为 property map 使用，是因为 BGL 为指针类型提供了 property map 的特化：顶点描述符（整数索引）作为 key，直接索引数组元素。

5.3 常用的 Property Map 适配器

适配器 用途
iterator_property_map 将迭代器包装为 property map，支持任意 key 类型
make_iterator_property_map 便捷工厂函数
ref_property_map 包装单个值
compose_property_map 组合两个 property map
function_property_map 用函数/ lambda 动态计算属性值

#include <boost/graph/dijkstra_shortest_paths.hpp>

std::vector<int>    dist(num_vertices(g));
std::vector<Vertex> pred(num_vertices(g));

Vertex start = 0;
dijkstra_shortest_paths(g, start,
    boost::distance_map(&dist[0])
        .predecessor_map(&pred[0])
        .weight_map(get(boost::edge_weight, g)));  // 带权图需要指定 weight_map

// 还原最短路径：
Vertex target = 4;
std::vector<Vertex> path;
for (Vertex v = target; v != start; v = pred[v])
    path.push_back(v);
path.push_back(start);
std::reverse(path.begin(), path.end());
// path 现在是从 start 到 target 的最短路径顶点序列

7. Visitor —— 算法事件注入

Visitor 是 BGL 中扩展算法的核心机制。每个算法在执行过程中会在特定时机触发"事件"，Visitor 可以在这些事件点注入自定义逻辑。

以 Dijkstra 算法为例，它定义了以下事件：

事件 触发时机
initialize_vertex 算法开始时，每个顶点初始化
discover_vertex 顶点首次被发现
examine_vertex 顶点从优先队列中取出，准备处理
examine_edge 检查某条边是否放松
edge_relaxed 边放松成功，目标的距离被更新
edge_not_relaxed 边放松失败（距离未更新）
finish_vertex 顶点的所有出边都处理完毕

template <typename PredecessorMap>
struct record_predecessors : public boost::dijkstra_visitor<> {
    PredecessorMap m_pred;

    record_predecessors(PredecessorMap p) : m_pred(p) {}

    template <typename Edge, typename Graph>
    void edge_relaxed(Edge e, const Graph& g) {
        // 当边松驰成功时，target 的前驱就是 source
        put(m_pred, target(e, g), source(e, g));
    }
};

// 使用自定义 visitor 的便捷工厂：
template <typename PredecessorMap>
record_predecessors<PredecessorMap>
make_record_predecessors(PredecessorMap p) {
    return record_predecessors<PredecessorMap>(p);
}

9. 小结

BGL 的设计可以总结为三条主线：

  1. 泛型图抽象 —— graph_traits + 概念体系让算法与具体图数据结构解耦，同一套算法可以作用于 adjacency_list、自定义邻接矩阵，甚至外部图库的数据结构。
  2. Property Map —— 统一的内/外部属性访问接口，将"数据存储在哪"与"算法如何使用数据"分开。
  3. Visitor —— 事件驱动的行为注入机制，在算法框架的关键节点挂载自定义逻辑。

理解这三条主线，就能理解 BGL 的全部设计。
