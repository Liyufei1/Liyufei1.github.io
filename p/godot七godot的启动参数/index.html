Godot 4.4 启动参数完整指南

Godot 引擎提供了丰富的命令行启动参数，允许开发者在运行时和编辑器中精细控制引擎行为。本文基于 Godot 4.4 源码，全面梳理了所有可用的启动参数，并按功能分类进行详细介绍。

基本参数

-h, --help, /?

显示帮助信息并退出。这是获取所有可用命令行参数的最快方法。

1

godot --help

使用场景：

  • 初次使用 Godot 时了解可用参数
  • 忘记具体参数名称时快速查阅
  • 检查当前 Godot 版本支持的参数列表

--version

显示 Godot 版本信息并退出。

1

godot --version

使用场景：

  • 确认当前使用的 Godot 版本
  • 在 CI/CD 环境中验证引擎版本
  • 报告问题时提供版本信息

-v, --verbose

启用详细输出模式，打印更多信息到控制台。包括引擎初始化、资源加载、错误详情等。

1

godot --verbose

使用场景：

  • 调试启动问题
  • 查看资源加载过程
  • 分析引擎初始化流程
  • 开发和测试环境中获取更多信息

-q, --quiet

启用安静模式，减少控制台输出。仅显示错误信息，适用于自动化脚本。

1

godot --quiet

使用场景：

  • CI/CD 环境中减少日志噪音
  • 自动化构建脚本
  • 批量处理任务
  • 生产环境部署

--no-header

禁用启动时显示的 Godot 标题头信息，使输出更加简洁。

1

godot --no-header

使用场景：

  • 脚本化操作时保持输出整洁
  • 日志分析时减少无关信息
  • 自动化测试环境

运行时参数

--path <path>

指定项目路径。这是最重要的参数之一，告诉 Godot 在哪里找到项目。

1

godot --path /path/to/project

使用场景：

  • 从任意目录运行 Godot 项目
  • 在脚本中指定项目位置
  • CI/CD 管道中的项目路径配置

最佳实践：

  • 优先使用绝对路径以确保可靠性
  • 在自动化脚本中总是明确指定项目路径
  • 路径应包含 project.godot 文件

-u, --upwards

向上扫描文件夹以查找 project.godot 文件。从当前目录开始递归搜索父目录。

1

godot --upwards

使用场景：

  • 在项目子目录中快速运行 Godot
  • 开发环境中的便捷操作
  • 不需要记住完整项目路径的快速启动

最佳实践：

  • 适用于开发环境，生产环境建议使用 --path
  • 确保项目目录结构清晰，避免多个 project.godot 文件

--main-pack <path>

指定主包文件路径。允许从 PCK 文件运行项目，无需源代码。

1

godot --main-pack /path/to/main.pck

使用场景：

  • 运行打包后的游戏
  • 分发游戏而不暴露源代码
  • 模块化项目部署

最佳实践：

  • 确保 PCK 文件与引擎版本兼容
  • 用于最终产品分发，不用于开发

--quit

在第一个主循环迭代后自动退出。用于快速测试和验证。

1

godot --quit

使用场景：

  • 验证项目配置是否正确
  • 快速检查脚本语法错误
  • CI/CD 中的快速验证步骤

最佳实践：

  • 结合 --verbose 使用以获取错误信息
  • 用于自动化测试的第一步验证

--quit-after <n>

在指定数量的迭代后退出。允许运行特定帧数后自动退出。

1

godot --quit-after 100

使用场景：

  • 性能测试的固定时长
  • 自动化截图或录制
  • 有限时长的测试场景

最佳实践：

  • 结合 --fixed-fps 使用以获得精确的时间控制
  • 用于自动化测试和性能基准测试

--max-fps <n>

设置最大渲染帧率。0 表示不限制帧率。

1

godot --max-fps 60

使用场景：

  • 限制 CPU/GPU 使用率
  • 移动设备省电
  • 保持一致的帧率
  • 性能测试

最佳实践：

  • 移动平台通常设置为 30 或 60 FPS
  • 桌面平台可以不限制或设置为显示器刷新率
  • 用于性能优化时，逐步降低帧率测试

--fixed-fps <n>

设置固定帧率模式。禁用实时同步，强制固定时间步长。

1

godot --fixed-fps 30

使用场景：

  • 物理模拟需要固定时间步长
  • 录制游戏视频时确保一致性
  • 网络同步游戏
  • 调试时间相关问题

最佳实践：

  • 物理游戏通常使用 60 FPS 的固定帧率
  • 录制视频时根据目标帧率设置
  • 不适用于需要实时响应的游戏

--frame-delay <ms>

设置帧延迟（毫秒）。模拟高 CPU 负载情况。

1

godot --frame-delay 16

使用场景：

  • 模拟低端设备性能
  • 测试游戏在慢速环境下的表现
  • 性能压力测试

最佳实践：

  • 不要用作 FPS 限制器，应使用 --max-fps
  • 用于性能测试和优化验证
  • 典型值为 16ms（60 FPS）或 33ms（30 FPS）

--time-scale <scale>

设置时间缩放因子。1.0 为正常速度，更高值更快，更低值更慢。

1

godot --time-scale 0.5

使用场景：

  • 慢动作效果测试
  • 快速测试长时间运行的游戏
  • 调试时间相关的游戏机制
  • 性能测试中的时间加速

最佳实践：

  • 0.5 用于慢动作调试
  • 2.0 或更高用于快速测试
  • 结合 --fixed-fps 获得可重现的结果

--delta-smoothing <mode>

设置增量平滑模式（enable/disable）。控制帧时间平滑以减少抖动。

1

godot --delta-smoothing enable

使用场景：

  • 提高动画和物理的平滑度
  • 减少帧率波动的影响
  • 调试时间相关问题

最佳实践：

  • 默认启用以获得更好的游戏体验
  • 调试时可以禁用以查看原始帧时间
  • 在固定帧率模式下通常不需要

注意事项

参数使用原则

  1. 参数顺序：某些参数的顺序很重要，特别是路径相关参数。

    • --path 应该在其他需要项目上下文的参数之前
    • --headless 通常放在前面以避免不必要的初始化
    • 场景文件路径应该在最后

  2. 平台差异：部分参数仅在特定平台上可用。

    • macOS 需要使用 .app 包内的可执行文件
    • Windows 和 Linux 可以直接运行二进制文件
    • 移动平台的参数支持有限

  3. 版本兼容性：不同版本的 Godot 可能支持不同的参数。

    • 新版本可能添加新参数或废弃旧参数
    • 某些参数的行为可能在不同版本间有差异
    • 建议查看对应版本的官方文档

性能考虑

  1. 性能影响：调试和性能分析参数可能会显著影响运行性能。

    • --debug 会降低运行性能，仅用于开发阶段
    • --profiling 和 --profile-gpu 会增加开销
    • --verbose 会产生大量输出，影响 I/O 性能
    • 发布版本中禁用所有调试参数

  2. 资源管理：某些参数会影响内存和资源使用。

    • --extra-gpu-memory-tracking 会增加内存使用
    • --write-movie 需要大量磁盘空间
    • --profiling 会收集大量数据

安全考虑

  1. 安全考虑：远程调试和文件系统参数在生产环境中应谨慎使用。
    • --remote-debug 可能暴露安全漏洞
    • --remote-fs 涉及网络文件系统访问
    • 避免在生产环境启用调试功能
    • 使用防火墙限制调试端口访问

常见问题和解决方案

  1. 路径问题：

    • 使用绝对路径避免相对路径问题
    • Windows 路径使用反斜杠，Unix 使用正斜杠
    • 确保路径中不包含特殊字符或空格（或使用引号）

  2. 权限问题：

    • 确保对项目目录有读写权限
    • 检查日志文件的写入权限
    • 某些参数可能需要管理员权限

  3. 兼容性问题：

    • 检查 Godot 版本与项目兼容性
    • 确保导出模板版本匹配
    • 验证依赖项和插件兼容性

  4. 环境配置：

    • 确保系统环境变量正确设置
    • 检查图形驱动程序兼容性
    • 验证音频驱动可用性

最佳实践总结

  1. 开发环境：

    • 使用 --verbose 获取详细信息
    • 启用适当的调试参数
    • 使用版本控制管理项目

  2. 测试环境：

    • 模拟目标环境配置
    • 使用自动化测试脚本
    • 记录测试结果和性能数据

  3. 生产环境：

    • 禁用所有调试参数
    • 使用 --quiet 减少日志输出
    • 配置适当的日志轮转

  4. CI/CD 环境：

    • 始终使用 --headless
    • 配置适当的超时时间
    • 使用明确的错误处理

    • 建立性能基准线

Error Main::setup(const char *execpath, int argc, char *argv[], bool p_second_phase) {
    // ...
        
    // 命令行参数解析循环
    while (I) {
        List<String>::Element *N = I->next();
        const String &arg = I->get();

        // 1. --help 参数处理
        if (arg == "-h" || arg == "--help" || arg == "/?") {
            show_help = true;
            exit_err = ERR_HELP; // 强制早期退出，返回成功代码
            goto error;
        }
        
        // 2. --remote-debug 参数处理
        else if (arg == "--remote-debug") {
            if (N) {
                debug_uri = N->get();
                if (!debug_uri.contains("://")) { // 验证地址格式
                    OS::get_singleton()->print(
                        "Invalid debug host address, it should be of the form <protocol>://<host/IP>:<port>.\n");
                    goto error;
                }
                N = N->next();
            } else {
                OS::get_singleton()->print("Missing remote debug host address, aborting.\n");
                goto error;
            }
        }
        
        // 3. --max-fps 参数处理
        else if (arg == "--max-fps") {
            if (N) {
                max_fps = N->get().to_int();
                N = N->next();
            } else {
                OS::get_singleton()->print("Missing maximum FPS argument, aborting.\n");
                goto error;
            }
        }
        
        // 4. --time-scale 参数处理 以及实现
        else if (arg == "--time-scale") {
            if (N) {
                // 设置时间缩放
                Engine::get_singleton()->set_time_scale(N->get().to_float());
                N = N->next();
            } else {
                OS::get_singleton()->print("Missing time scale argument, aborting.\n");
                goto error;
            }
        }
        
        I = N;

        //1. --help 的实现
        if (show_help) {
            print_help(execpath);
        }

        // 2. --remote-debug 的实现
        EngineDebugger::initialize(debug_uri, skip_breakpoints, breakpoints, []() {
            if (editor_pid) {
                DisplayServer::get_singleton()->enable_for_stealing_focus(editor_pid);
            }
	    });

        // 3. --max-fps 的实现
        Engine::get_singleton()->set_max_fps(GLOBAL_DEF(PropertyInfo(Variant::INT, "application/run/max_fps", PROPERTY_HINT_RANGE, "0,1000,1"), 0));
        if (max_fps >= 0) {
            Engine::get_singleton()->set_max_fps(max_fps);
        }
    }
}
