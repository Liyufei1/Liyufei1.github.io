第1章 计算机系统漫游

1.1 编译系统

一个 C 程序从源文件到最终的可执行文件，通常会经历以下四个阶段：

  • 预处理：处理源代码中的宏展开、头文件包含和条件编译等指令，删除注释后生成预处理文件。
  • 编译：对预处理后的代码进行词法分析、语法分析和语义分析，并生成对应的汇编代码。
  • 汇编：将汇编代码翻译为机器指令，生成目标文件。
  • 链接：将多个目标文件以及所需的库文件链接在一起，解析符号引用，最终生成可执行文件。

可以把这一过程理解为：先“整理”源代码，再“翻译”为汇编，再“转换”为机器指令，最后把程序运行所需的各个部分“拼装”起来。

1.2 计算机硬件组成

一个典型的计算机系统通常由以下几个核心部分组成：

  1. CPU（Central Processing Unit，中央处理器）
    1. PC（Program Counter，程序计数器）：本质是一个大小为一个字的存储单元(32bit/64bit)，保存下一条将要执行的指令地址。
    2. Register（寄存器）：CPU 内部用于暂存数据和中间结果的高速存储单元。
    3. ALU（Arithmetic Logic Unit，算术逻辑单元）：负责执行加、减、与、或等算术和逻辑运算。
    4. Bus（总线）：负责在 CPU 内部以及 CPU 与其他部件之间传输数据、地址和控制信号。
  2. Main Memory（主存，也就是内存）：保存程序运行时的指令和数据。可以把它看成一个按字节编址的大数组，每个字节都有唯一的地址。
  3. I/O Bridge（输入输出桥接器）：负责连接处理器、内存与外部 I/O 设备，协调不同部件之间的数据交换。
  4. I/O Bus（输入输出总线）：为磁盘、键盘、显示器、网络设备等外设提供数据传输通道。

从功能上看，CPU 负责“运算”，主存负责“存储”，而 I/O 系统则负责“与外界交互”，三者共同构成了一个完整的计算机系统。

在存储层次结构中，越靠上的存储设备速度越快，但容量越小、成本也越高；越靠下的存储设备容量越大，但访问速度越慢。

可以把这一结构理解为一个“存储金字塔”：上层存储通常作为下层存储的高速缓冲，从而在容量、成本和速度之间取得平衡。
因此，程序之所以能够高效运行，很大程度上依赖于这种分层存储设计。

1.3 操作系统硬件管理

应用程序通常不能直接操作底层硬件，而是要通过操作系统提供的接口来完成。
操作系统位于应用程序与硬件之间，负责对底层资源进行统一管理，并向上层提供更简单、更安全的抽象。

从 CSAPP 的视角来看，操作系统主要通过以下三种抽象来管理硬件资源：

  • Process（进程）：对处理器、内存和 I/O 设备的抽象。进程为程序提供了“独占使用计算机”的假象，使程序能够在相互隔离的环境中运行。
  • Virtual Memory（虚拟内存）：对主存和磁盘空间的抽象。每个进程都认为自己拥有一块连续、私有的地址空间，而无需直接感知物理内存的实际布局。
  • File（文件）：对 I/O 设备的抽象。无论是磁盘、键盘、显示器，还是网络设备，操作系统都尽量用统一的文件式接口来组织和访问数据。

这三种抽象降低了应用程序直接操作硬件的复杂度，也让系统在安全性、可移植性和并发执行方面更容易实现。

以一个进程的虚拟地址空间为例，通常可以划分为以下几个区域：

  • 代码区：保存程序的机器指令，通常是只读的。
  • 数据区：保存全局变量和静态变量等数据。
  • 堆区：用于程序运行时的动态内存分配，例如 malloc 申请的空间通常位于堆中。
  • 共享库映射区：用于加载动态链接库以及其他内存映射区域。
  • 栈区：用于保存函数调用过程中的局部变量、返回地址和参数等信息。
  • 内核空间：由操作系统内核保留，用户程序不能直接访问。

其中，堆通常向高地址方向增长，栈通常向低地址方向增长。
这种布局方式使进程能够较高效地管理动态分配和函数调用所需的内存空间。

第2章 信息的表示和处理

2.1 信息存储

计算机中的信息最终都是以二进制形式存储的，而这些二进制数据通常按字节组织。
不同机器的字长可能不同，例如常见的有 32 位和 64 位，这会影响指针、整数等数据类型所占用的字节数。

从图中可以看出：

  • 在 32 位机器上，指针通常占 4 个字节，long 通常也占 4 个字节。
  • 在 64 位机器上，指针通常占 8 个字节，long 在很多 64 位系统上也占 8 个字节。

需要注意的是，数据类型的实际大小不仅与机器字长有关，也与编译器实现和平台约定有关。因此在编写底层代码时，不能只凭经验判断类型大小，最好结合具体平台确认。

除了“占多少字节”之外，数据在内存中“如何排列字节”也非常重要，这就是字节序问题。

常见的字节序有两种：

  • 大端序（Big-Endian）：最高有效字节存放在低地址处。
  • 小端序（Little-Endian）：最低有效字节存放在低地址处。

目前常见的 PC 和大多数 Android 设备通常都采用小端序。
理解字节序对于分析内存布局、网络传输协议、二进制文件格式以及调试程序都很重要。

2.2 整数表示

  • 无符号整数（Unsigned）：所有位都用于表示数值本身，因此只能表示非负数。
    • 最小值：0
    • 最大值：2^w - 1
  • 有符号整数（Signed）：通常使用补码表示，这样既可以表示正数，也可以表示负数。
    • 最小值：-2^(w-1)
    • 最大值：2^(w-1) - 1


从二进制转换到十进制时：

  • 对于无符号数，可以直接按每一位的权重求和。
  • 对于补码表示的有符号数，如果最高位为 0，表示非负数，转换方式与无符号数类似；如果最高位为 1，则表示负数，需要按补码规则解释其值。

  • 大类型转换为小类型时，会直接截断并丢失精度。
  • 小类型转换为大类型时，会进行扩展，并保留精度。
