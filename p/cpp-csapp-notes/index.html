第1章 计算机系统漫游

1.1 编译系统

一个 C 程序从源文件到最终的可执行文件，通常会经历以下四个阶段：

  • 预处理：处理源代码中的宏展开、头文件包含和条件编译等指令，删除注释后生成预处理文件。
  • 编译：对预处理后的代码进行词法分析、语法分析和语义分析，并生成对应的汇编代码。
  • 汇编：将汇编代码翻译为机器指令，生成目标文件。
  • 链接：将多个目标文件以及所需的库文件链接在一起，解析符号引用，最终生成可执行文件。

可以把这一过程理解为：先“整理”源代码，再“翻译”为汇编，再“转换”为机器指令，最后把程序运行所需的各个部分“拼装”起来。

1.2 计算机硬件组成

一个典型的计算机系统通常由以下几个核心部分组成：

  1. CPU（Central Processing Unit，中央处理器）
    1. PC（Program Counter，程序计数器）：本质是一个大小为一个字的存储单元(32bit/64bit)，保存下一条将要执行的指令地址。
    2. Register（寄存器）：CPU 内部用于暂存数据和中间结果的高速存储单元。
    3. ALU（Arithmetic Logic Unit，算术逻辑单元）：负责执行加、减、与、或等算术和逻辑运算。
    4. Bus（总线）：负责在 CPU 内部以及 CPU 与其他部件之间传输数据、地址和控制信号。
  2. Main Memory（主存，也就是内存）：保存程序运行时的指令和数据。可以把它看成一个按字节编址的大数组，每个字节都有唯一的地址。
  3. I/O Bridge（输入输出桥接器）：负责连接处理器、内存与外部 I/O 设备，协调不同部件之间的数据交换。
  4. I/O Bus（输入输出总线）：为磁盘、键盘、显示器、网络设备等外设提供数据传输通道。

从功能上看，CPU 负责“运算”，主存负责“存储”，而 I/O 系统则负责“与外界交互”，三者共同构成了一个完整的计算机系统。

在存储层次结构中，越靠上的存储设备速度越快，但容量越小、成本也越高；越靠下的存储设备容量越大，但访问速度越慢。

可以把这一结构理解为一个“存储金字塔”：上层存储通常作为下层存储的高速缓冲，从而在容量、成本和速度之间取得平衡。
因此，程序之所以能够高效运行，很大程度上依赖于这种分层存储设计。

1.3 操作系统硬件管理

应用程序通常不能直接操作底层硬件，而是要通过操作系统提供的接口来完成。
操作系统位于应用程序与硬件之间，负责对底层资源进行统一管理，并向上层提供更简单、更安全的抽象。

从 CSAPP 的视角来看，操作系统主要通过以下三种抽象来管理硬件资源：

  • Process（进程）：对处理器、内存和 I/O 设备的抽象。进程为程序提供了“独占使用计算机”的假象，使程序能够在相互隔离的环境中运行。
  • Virtual Memory（虚拟内存）：对主存和磁盘空间的抽象。每个进程都认为自己拥有一块连续、私有的地址空间，而无需直接感知物理内存的实际布局。
  • File（文件）：对 I/O 设备的抽象。无论是磁盘、键盘、显示器，还是网络设备，操作系统都尽量用统一的文件式接口来组织和访问数据。

这三种抽象降低了应用程序直接操作硬件的复杂度，也让系统在安全性、可移植性和并发执行方面更容易实现。

以一个进程的虚拟地址空间为例，通常可以划分为以下几个区域：

  • 代码区：保存程序的机器指令，通常是只读的。
  • 数据区：保存全局变量和静态变量等数据。
  • 堆区：用于程序运行时的动态内存分配，例如 malloc 申请的空间通常位于堆中。
  • 共享库映射区：用于加载动态链接库以及其他内存映射区域。
  • 栈区：用于保存函数调用过程中的局部变量、返回地址和参数等信息。
  • 内核空间：由操作系统内核保留，用户程序不能直接访问。

其中，堆通常向高地址方向增长，栈通常向低地址方向增长。
这种布局方式使进程能够较高效地管理动态分配和函数调用所需的内存空间。

第2章 信息的表示和处理

2.1 信息存储

计算机中的信息最终都是以二进制形式存储的，而这些二进制数据通常按字节组织。
不同机器的字长可能不同，例如常见的有 32 位和 64 位，这会影响指针、整数等数据类型所占用的字节数。

从图中可以看出：

  • 在 32 位机器上，指针通常占 4 个字节，long 通常也占 4 个字节。
  • 在 64 位机器上，指针通常占 8 个字节，long 在很多 64 位系统上也占 8 个字节。

需要注意的是，数据类型的实际大小不仅与机器字长有关，也与编译器实现和平台约定有关。因此在编写底层代码时，不能只凭经验判断类型大小，最好结合具体平台确认。

除了“占多少字节”之外，数据在内存中“如何排列字节”也非常重要，这就是字节序问题。

常见的字节序有两种：

  • 大端序（Big-Endian）：最高有效字节存放在低地址处。
  • 小端序（Little-Endian）：最低有效字节存放在低地址处。

目前常见的 PC 和大多数 Android 设备通常都采用小端序。
理解字节序对于分析内存布局、网络传输协议、二进制文件格式以及调试程序都很重要。

2.2 整数表示

  • 无符号整数（Unsigned）：所有位都用于表示数值本身，因此只能表示非负数。
    • 最小值：0
    • 最大值：2^w - 1
  • 有符号整数（Signed）：通常使用补码表示，这样既可以表示正数，也可以表示负数。
    • 最小值：-2^(w-1)
    • 最大值：2^(w-1) - 1


从二进制转换到十进制时：

  • 对于无符号数，可以直接按每一位的权重求和。
  • 对于补码表示的有符号数，如果最高位为 0，表示非负数，转换方式与无符号数类似；如果最高位为 1，则表示负数，需要按补码规则解释其值。


由于补码规则的存在，在进行强制类型转换时，会出现直接预期之外的结果。
上方结果是由于int被隐式类型转换为unsigned int导致的。

  • 大类型转换为小类型时，会直接截断并丢失精度。
  • 小类型转换为大类型时，会进行扩展，并保留精度。

2.3 整数运算

整数的加减法

对于无符号数，整数相加等于二进制位的直接相加。当结果超过表示范围时，会发生溢出，溢出的位会被丢弃。

对于有符号数，由于采用补码表示，加法运算可以同样通过二进制位直接完成——CPU 不区分有符号和无符号，统一按二进制运算。但需要注意的是，有符号数的溢出行为是未定义的，编译器不会对此进行任何检查或提醒。

整数的乘法

整数乘法可以拆分成左移运算和相加运算。以 $x \times 13$ 为例：

$$x \times 13 = x \times (2^3 + 2^2 + 2^0) = (x \ll 3) + (x \ll 2) + x$$

在硬件层面，ALU 通过移位和加法的组合来实现乘法，因此乘法指令的周期数通常远大于加法和移位。

无符号乘法与有符号乘法在二进制层面的运算相同，区别仅在于最高位的解释方式。

整数的除法

整数除法同样可以借助移位来实现，但需要注意截断规则：

  • 无符号数除以 $2^k$：右移 $k$ 位，低位直接丢弃。
  • 有符号数除以 $2^k$：右移 $k$ 位，但负数的截断方式不同，向上取整（向 0 的方向取整）。

有符号数右移时采用算术右移，即高位补符号位（0 表示正，1 表示负）。这意味着负数右移后结果会向 0 的方向取整，而不是向下取整。

示例：

表达式 结果 说明
-7 / 2 -3 向 0 取整
(-7) >> 1 -4 算术右移，向下取整

如果需要向下取整，可以使用如下技巧：

$$ \lfloor x / 2^k \rfloor = (x + 2^k - 1) \gg k \quad (x \ge 0) $$

$$ \lfloor x / 2^k \rfloor = (x + 2^k - 1) \mid \sim(2^k - 1) \gg k \quad (x < 0) $$

第3章 程序的机器级表示

3.1 汇编基础与寄存器

程序的机器级表示，是理解计算机执行机制的核心。与高级语言屏蔽底层细节不同，汇编语言直接反映了 CPU 的运行逻辑——指令如何读写寄存器、如何访问内存、如何跳转。

调用者保存寄存器与被调用者保存寄存器

在 x86-64 架构中，寄存器一共 16 个：rax, rbx, rcx, rdx, rsi, rdi, rbp, rsp, r8~r15。其中有 8 个通用寄存器，它们的使用在函数调用时有明确约定。

调用者保存寄存器（Caller-saved，也叫 Caller-clobbered）： rax, rcx, rdx, rsi, rdi, r8, r9, r10, r11

调用者保存的含义是：若一个寄存器在调用子函数前有值，调用者需要自己负责保存（压栈或转移到其他寄存器），因为被调用函数可能会修改它们。子函数可以自由使用这些寄存器而无需保留它们的值。

被调用者保存寄存器（Callee-saved）： rbx, rbp, r12, r13, r14, r15, rsp

被调用者保存的含义是：若子函数要使用这些寄存器，必须先将原始值压栈保存，在返回前恢复原值。rsp 特殊一些，它指向栈顶，恢复后才能正确返回。

这种划分本质上是一种调用约定（Calling Convention），让调用者和被调用者就寄存器的使用规则达成一致。编译器正是依据这套规则生成机器码的。

汇编指令后缀与操作数大小

后缀 大小 典型用途
b 1 字节 movb, addb
w 2 字节 movw, addw
l 4 字节 movl, addl（32位）
q 8 字节 movq, addq（64位）

mov 系列指令是出现频率最高的指令之一，格式为 movx source, dest，将 source 的值复制到 dest。

3.2 寄存器和数据传输指令

x86-64 各寄存器的用途有一定约定，虽然部分可以混用，但遵循约定能让代码更易读。

常见用途：

  • rax —— 返回值寄存器，也用于做累加器
  • rdi —— 第一个参数
  • rsi —— 第二个参数
  • rdx —— 第三个参数
  • rcx —— 第四个参数
  • r8~r9 —— 第五、六个参数
  • rsp —— 栈指针，指向栈顶
  • rbp —— 基址指针，常用于栈帧定位

常见数据传输指令：

1
2
3
4

mov rax, rbx      ; 将 rbx 的值复制到 rax
mov rax, [rbx]    ; 从 rbx 指向的内存地址读取值到 rax（内存→寄存器）
mov [rax], rbx    ; 将 rbx 的值写入 rax 指向的内存地址（寄存器→内存）
lea rax, [rbx+8]  ; 计算 rbx+8 的地址，载入 rax（注意：不是读取该地址的值）

mov 禁止内存到内存的直接传输，必须经过寄存器中转。lea 是取地址指令，常用于计算表达式结果而不访问内存。

3.3 栈与函数调用

栈是程序运行时最重要的内存区域之一，用于函数调用、局部变量存储和寄存器保存。

栈的生长方向：栈向下生长——每 push 一个值，rsp 减小；每 pop 一个值，rsp 增大。

函数调用三部曲：

  1. 调用前：将参数放入 rdi, rsi, rdx, rcx, r8, r9（多余参数压栈）
  2. 调用时：call 指令将返回地址压栈，跳转到被调用函数
  3. 返回时：ret 从栈中弹出返回地址，跳回调用者

典型函数 prologue（开篇）：

1
2
3

push rbp           ; 保存调用者的基址指针
mov rbp, rsp       ; 建立新的栈帧基址
sub rsp, 32        ; 分配 32 字节本地变量空间

典型函数 epilogue（收尾）：

1
2
3

add rsp, 32        ; 释放本地变量空间
pop rbp            ; 恢复调用者的基址指针
ret                ; 返回

也可以用 leave 代替 pop rbp; mov rsp, rbp，leave 相当于同时完成这两步。

为什么要用基址指针 rbp：有了 rbp，无论栈上分配了多少本地变量，都能通过固定偏移量访问它们，因为 rbp 在整个函数执行期间指向栈帧的固定位置。

3.4 算术与逻辑运算符

x86-64 提供了一组丰富的算术指令，大多是二操作数形式 op src, dest，等价于 dest = dest op src。

算术指令：

指令 操作 说明
add 加法 add rax, rbx → rax += rbx
sub 减法 sub rax, rbx → rax -= rbx
imul 有符号乘法 结果存于 rdx:rax（128位）
mul 无符号乘法 同上
idiv 有符号除法 rdx:rax ÷ rdi，商→rax，余→rdx
div 无符号除法 同上
inc 加 1 inc rax → rax++
dec 减 1 dec rax → rax--
neg 取负 neg rax → rax = -rax

移位指令：

指令 操作
sal / shl 算术左移 / 逻辑左移（效果相同）
sar 算术右移（高位补符号位）
shr 逻辑右移（高位补 0）

移位量可以是立即数或 cl 寄存器（只取低 5 位，所以最大移位量为 31，适用于 32/64 位）。

逻辑指令：

指令 操作
and 按位与
or 按位或
xor 按位异或
not 按位取反

xor rax, rax 是将 rax 置零的经典写法，比 mov rax, 0 更短且同样高效。

条件码（Condition Codes）：

大多数算术指令会隐式设置四个标志位：

  • CF —— 进位标志（无符号溢出）
  • ZF —— 零标志（结果为 0）
  • SF —— 符号标志（结果为负）
  • OF —— 有符号溢出标志

cmp 和 test 指令专门用来设置条件码而不改变目标操作数：

  • cmp b, a 相当于计算 a - b，根据结果设置标志位
  • test b, a 相当于计算 a & b，根据结果设置标志位

jmp、je、jne、jl、jle、jg、jge 等条件跳转指令依赖这些标志位决定是否跳转，这正是 if、while、for 等控制结构的底层实现。

3.5 分支与循环

高级语言中的 if-else、while、for 在汇编层主要靠条件跳转实现。

分支结构：

1
2
3
4
5

if (x < y) {
    // then branch
} else {
    // else branch
}

汇编思路：先用 cmp 比较，设置条件码，再根据条件码 jge（大于等于跳转）跳过 then 分支，或直接用 jl 进入 then 分支。

循环结构：

1
2
3
4

while (x > 0) {
    // body
    x--;
}

汇编思路：先跳转到条件判断处，比较后 jle（小于等于跳转）跳出循环，jmp 无条件跳转回条件判断处，形成循环。

循环的本质是条件跳转 + 无条件跳转的组合。

3.6 数组与指针运算

数组在内存中是连续排列的。对数组元素 a[i] 的访问，编译后通常等价于：

1

address = base + i * element_size

lea 指令特别适合做这种地址计算：lea rax, [rdi + rsi*8] 即可一次性完成 base + i*8 的地址计算。

C 语言中 a[i] 和 *(a+i) 完全等价，指针运算本质上就是地址运算。理解了这一层，就能看清数组越界访问的实质——访问了相邻内存区域。

3.7 缓冲区溢出

理解机器级表示的另一个重要意义是了解安全漏洞。缓冲区溢出（Buffer Overflow）是最经典的底层安全问题的根源。

当程序向一个固定大小的缓冲区写入超过其容量的数据时，超出部分会覆盖相邻的栈帧区域。如果攻击者精心构造输入，可以：

  • 覆盖函数返回地址，使 ret 时跳转到任意代码
  • 覆写被调用者保存寄存器，破坏调用者的数据
  • 写入可执行代码并让返回地址指向它（代码注入）

现代系统通过 栈保护金丝雀（Stack Canary）和 ** NX / DEP**（禁止栈上执行代码）等机制大幅缓解了这类攻击，但仍有很多漏洞以更隐蔽的方式存在。理解底层，是安全研究的基础。
