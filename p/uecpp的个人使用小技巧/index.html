日志

使用自定义日志类别

默认的 UE_LOG(LogTemp, ...) 所有人的日志混在一个类别里，既不方便筛选，也无法单独控制 Verbosity。建议每个模块都定义自己的日志类别。

1. 声明自定义 Log Category

在头文件中用 DECLARE_LOG_CATEGORY_EXTERN 声明：

1
2
3
4
5
6

// MyModule.h
#pragma once

#include "CoreMinimal.h"

DECLARE_LOG_CATEGORY_EXTERN(LogMyModule, Log, All);
  • 第一个参数：类别名（通常以 Log 开头）
  • 第二个参数：默认 Verbosity，编译后生效的默认级别
  • 第三个参数：编译时最高 Verbosity，超过这个级别的日志在编译期就会被剥离

在对应的 .cpp 中定义：

1
2
3
4

// MyModule.cpp
#include "MyModule.h"

DEFINE_LOG_CATEGORY(LogMyModule);

2. 常用 Verbosity 级别（从低到高）

级别 宏 用途
VeryVerbose LogMyModule(Verbose, ...) 极其详细的调试信息
Verbose LogMyModule(Verbose, ...) 详细调试日志
Log LogMyModule(Log, ...) 常规信息
Display LogMyModule(Display, ...) 默认输出到控制台
Warning LogMyModule(Warning, ...) 警告（黄色）
Error LogMyModule(Error, ...) 错误（红色），Message Log 中可见
Fatal LogMyModule(Fatal, ...) 致命错误，会崩溃

3. 使用示例 

1
2
3

UE_LOG(LogMyModule, Log, TEXT("Player %s spawned at %s"), *PlayerName, *SpawnLocation.ToString());
UE_LOG(LogMyModule, Warning, TEXT("Asset not found: %s"), *AssetPath);
UE_LOG(LogMyModule, Error, TEXT("Failed to initialize subsystem!"));

4. 实战：分模块定义日志类别

// 游戏玩法
DECLARE_LOG_CATEGORY_EXTERN(LogGameplay, Log, All);

// 网络相关（开发期看详细日志，发布后只留 Warning 以上）
DECLARE_LOG_CATEGORY_EXTERN(LogNet, Warning, All);

// AI 模块
DECLARE_LOG_CATEGORY_EXTERN(LogAI, Log, All);

// 性能敏感路径（编译期剥离 Verbose/Log，只保留 Warning+）
DECLARE_LOG_CATEGORY_EXTERN(LogPerf, Warning, Warning);

5. 控制台命令

运行时在控制台调整某个类别的 Verbosity：

1
2
3

Log LogMyModule Verbose          // 临时打开详细日志
Log LogMyModule Off              // 关闭该类别所有输出
Log LogNet Warning               // 设为 Warning 级别

6. 小技巧

  1. 头文件里如果只有一个类用，可以省掉 _EXTERN，直接在 .h 中用 DECLARE_LOG_CATEGORY（不要 DEFINE）——但要注意 .h 被多个 .cpp 包含时链接报错。
  2. Shipping 包体优化：将第三个参数设为 Warning，所有 Verbose/Log 级别的日志在编译期被剥离，零运行时开销。
  3. 带上上下文信息：UE_LOG 支持格式化字符串，建议始终带上关键变量值，比 GEngine->AddOnScreenDebugMessage 更灵活。
